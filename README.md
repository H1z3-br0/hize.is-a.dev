# Сайт-визитка

Статический сайт на Astro. Две версии: `/` — русская, `/en/` — английская.

В коде комментариев нет намеренно. Единственный комментарий на всём проекте —
первая часть флага в начале `<head>`, видна сразу по Ctrl+U. Всё, что раньше
объяснялось комментариями, собрано ниже в разделе «Грабли».

## Команды

```bash
npm install
npm run dev       # разработка, http://localhost:4321
npm run build     # обновить живые данные + собрать в dist/
npm run preview   # предпросмотр dist/ с теми же заголовками, что в проде
npm run check     # astro check
```

`npm run preview` повторяет `deploy/nginx.conf`: те же заголовки безопасности,
та же CSP, тот же ответ на `curl`, та же страница 404. Второй слой имеет смысл
проверять именно там, а не в `dev`.

## Где что править

**Весь текст и все данные — в `src/config/site.ts`.** Разметку трогать не нужно.
Пошаговые рецепты — в **[EDITING.md](EDITING.md)**.

| Что | Где |
|---|---|
| имя, позиционирование, «сейчас», проекты, контакты | `src/config/site.ts` |
| разделы страницы: порядок, id и подписи | там же, `sections` |
| стек по профилям | там же, `stack` |
| строки интерфейса, палитры и терминала | там же, `ui` и `shellText` |
| разборы CTF | там же, `writeups` — пустой массив, раздел не рендерится |
| условие криптозадачи и шифротекст | `src/config/challenge.json` |
| подписи задачи, части флага 1 и 2 | `src/config/challenge.ts` |
| палитра, кегль, ширина колонки | `src/styles/main.css`, блок `:root` |

### Как устроена синхронизация

Всё, что раньше пришлось бы держать согласованным руками, задаётся один раз:

- **Разделы.** Массив `sections` — единственный источник и для `id` в разметке,
  и для подписи в левом поле, и для якорей, и для пунктов палитры, и для команды
  `open` в терминале, и для заголовков в `card.txt`. Компонент `Section.astro`
  собирает `<section id>` и `<h2>` из него же, поэтому `id` и заголовок не могут
  разъехаться. Тип `SectionId` не даст сослаться на несуществующий раздел.
- **Раздел «разборы» появляется сам**, когда в `writeups` попадает первый
  элемент, — сразу везде: на странице, в палитре, в терминале и в обеих
  визитках. `visibleSections()` считает это в одном месте.
- **Профили стека** держат подпись рядом с инструментами: добавить профиль —
  один объект, больше нигде ничего.
- **Два языка.** `ui` и `shellText` объявлены как `Record<Lang, UiStrings>` и
  `Record<Lang, ShellStrings>`, поэтому забытый перевод — ошибка компиляции,
  а не пустое место на странице.

Проверить всё разом: `npm run check`.

### Что ещё не заполнено

- `identity.domain` — `null`, поэтому везде подставляется `localhost:4321`.
  Поставьте домен — он разойдётся по canonical, og, `security.txt`,
  `robots.txt` и подсказке `curl`. Тот же домен впишите в `deploy/nginx.conf`
  вместо `ПОСТАВЬТЕ_ДОМЕН` (два раза).
- `identity.pgp` — `null`, блок отпечатка не рендерится.
- `projects[0].repo` — репозиторий проекта про решётки не подтверждён.
- Развёрнутые тексты `Lambda` и «Инфраструктура для CTF».
- Текст блока «сейчас».
- `writeups` — пустой список.

## Живые данные

`npm run data` (входит в `build`) тянет последний коммит с GitHub
в `data/cache/live.json`. Правила:

- клиент в сеть не ходит никогда — всё вмораживается в HTML на сборке;
- недоступный API не роняет сборку: берётся закоммиченный кэш;
- нет ни сети, ни кэша — строка просто не рендерится.

`data/cache/live.json` коммитится, поэтому сборка проходит и без сети.

## Шрифты

STIX Two Text, сабсеты в `public/fonts/` (≈62 КБ на три файла), закоммичены.
Пересобрать:

```bash
python3 -m venv .venv && .venv/bin/pip install fonttools brotli
PATH=.venv/bin:$PATH ./tools/build-fonts.sh
```

## Картинка превью

```bash
node --experimental-strip-types tools/make-og.mjs
```

Перегенерируйте, если поменяли имя или позиционирование. `public/og.png`
коммитится, обычная сборка его не трогает.

## Второй слой

**Ответ на `curl`.** `curl <домен>` отдаёт текстовую визитку, а не HTML —
её собирает тот же билд из того же конфига (`src/lib/card.ts`). Язык
выбирается по `Accept-Language`. Руками: `/card.txt`, `/en/card.txt`.

**Палитра и терминал.** `Ctrl/Cmd + K`. Последний пункт палитры — `./secret`,
открывает терминал: `help`, `whoami`, `ls`, `cat`, `open`, `theme`, `lang`,
история стрелками, дополнение по Tab.

**Флаг из трёх частей.**

| Часть | Где лежит |
|---|---|
| 1 | HTML-комментарий в начале `<head>` |
| 2 | `robots.txt`, в base64 |
| 3 | выдача терминала после решения задачи |

Третья часть лежит в репозитории **только шифротекстом**: ключ выводится
PBKDF2-SHA256 (310 000 итераций) из ответа, им AES-GCM расшифровывает эту
часть. Ответа в репозитории нет, и проверять его не на чем — оракула не
существует, перебор упирается в KDF.

Поменять задачу и ответ:

```bash
node tools/make-challenge.mjs '<ответ>' '<третья часть флага>'
```

Скрипт перезапишет `src/config/challenge.json`; ответ никуда не сохраняется.
Условие (матрицу и цель) правьте там же в скрипте, подписи — в
`src/config/challenge.ts`.

## Деплой

Сайт статический: собрать и разложить файлы.

```bash
npm run build
rsync -az --delete dist/ user@host:/var/www/imam/
```

На сервере (Debian):

```bash
sudo cp deploy/nginx.conf /etc/nginx/sites-available/hize.is-a.dev
sudo ln -sf /etc/nginx/sites-available/hize.is-a.dev /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

`default` из `sites-enabled` нужно убрать: он тоже объявлен `default_server`,
а двух таких на одном порту nginx не допускает.

В конфиге уже прописаны `server_name hize.is-a.dev 151.241.109.127` и
`root /var/www/hize.is-a.dev/dist`, поэтому он работает и по IP, и по домену,
когда тот заработает.

Когда домен начнёт указывать на этот сервер, TLS добавляет certbot — он сам
допишет `listen 443 ssl`, пути к сертификату и редирект с 80-го порта в
существующий блок:

```bash
sudo certbot --nginx -d hize.is-a.dev
```

После этого поменяйте в `identity` (`src/config/site.ts`):

```ts
domain: "hize.is-a.dev",
https: true,
```

и пересоберите — адрес разойдётся по canonical, og, `security.txt`,
`sitemap.xml` и подсказке `curl`.

## Грабли

Три вещи, на которые легко наступить второй раз.

1. **`unicode-range` в `src/styles/main.css` не должен обещать больше, чем
   есть в шрифте.** Если диапазон объявляет символ, которого в сабсете нет,
   браузер выберет это начертание, глифа не найдёт и нарисует квадрат —
   в фолбэк он уже не уйдёт. Так было с `ₙ` (U+2099): его нет ни в
   STIX Two Text, ни в STIX Two Math. Надстрочные и подстрочные символы,
   которых нет в шрифте, набираются разметкой `<sup>` / `<sub>`
   в поле `notation` (оно рендерится через `set:html`), а в обычных абзацах
   — обычными знаками: `GL(n, ℤ)`, а не `GLₙ(ℤ)`.
   Диапазоны в CSS обязаны совпадать с `tools/build-fonts.sh`.

2. **`requestAnimationFrame` не тикает в скрытой вкладке.** Анимация редукции
   замерла бы на полушаге, поэтому `src/scripts/hero.ts` слушает
   `visibilitychange` и досчитывает базис до конца, а паузы между шагами
   держит на `setTimeout`, а не на rAF.

3. **Точки решётки выводятся из базиса, а не нарисованы как ℤ².** Во время
   редукции они стоят на месте (`|det|` = 1, решётка та же), а если
   перетащить вектор и сделать `|det|` больше единицы — честно разрежаются.
   Считаются через обратную матрицу: перебор коэффициентов у почти
   вырожденного базиса оставляет в сетке дыры.

## Что держится на честном слове

- **Весь контент читается при отключённом JS.** Без него нет решётки, палитры,
  терминала и переключателя темы — всё остальное работает, включая обе версии.
- Инлайновых скриптов и стилей нет, поэтому CSP обходится без `unsafe-inline`.
- Сторонних доменов нет: ни шрифтов, ни аналитики, ни счётчиков.
